# Deep Strike Map Update Workflow

Используй этот навык при вызове команды `/map [дата]` или когда пользователь просит собрать, проверить и добавить данные об ударах дальнего радиуса действия (deep strikes) по объектам в РФ за определенную дату.

## Входные данные
- **Дата:** Берется из сообщения пользователя (например, `/map 1 октября 2026`). Если дата не указана явно в запросе, запроси дату у пользователя либо уточни по контексту.
- **Временной диапазон:** Строго с 00:00 до 24:00 указанной даты (UTC+3, Киев/МСК). Другие даты и другое время в другие даты — строго не рассматривать.

## Задача 1: OSINT-мониторинг и сбор объектов

Ты выступаешь в роли OSINT-аналитика и специалиста по мониторингу военных конфликтов.

### 1.1. Строгие критерии отбора (в фокусе ТОЛЬКО):
- Объекты нефтегазовой промышленности;
- Военно-промышленного комплекса (ВПК);
- Нефтеперерабатывающие заводы (НПЗ);
- Нефтебазы, склады хранения горючего, нефтяные и газовые резервуары;
- Газовые терминалы, газо- и нефте-распределительные станции;
- Любая нефте-газовая инфраструктура;
- Заводы химической промышленности, машиностроения и любые другие предприятия, работающие на ВПК: КБ, НИИ и любые производства, важные для войны, выпуска военной техники и боеприпасов;
- Военные аэродромы;
- Логистические центры (WB, OZON, Яндекс и др.).

> [!WARNING]
> Всё подряд, что не касается указанных выше категорий (тактические склады БК на линии фронта, полевые позиции, гражданские объекты без военной логистики) — **СТРОГО НЕ ЗАПИСЫВАТЬ**!

### 1.2. Приоритет источников:
1. **Приоритетные:** Официальные заявления спецслужб и ведомств Украины (СБУ, ГУР МО, Силы беспилотных систем (СБС), ССО, Генштаб ВСУ), официальные обращения руководства Украины, авторитетные украинские СМИ и признанные OSINT-аналитики.
2. **Вспомогательные:** Официальные сообщения РФ или локальные паблики — использовать исключительно для кросс-верификации геолокации и подтверждения факта возгорания/взрыва.

### 1.3. Формат записи в базу `data.js`:
Структура объекта (код массива в итоговый отчет пользователю выводить **не нужно**):
```javascript
{
  "date": "01.10.2026",
  "lat": 57.1086,
  "lng": 65.6583,
  "distance": null, // рассчитывается автоматически скриптом calc.js
  "ru": {
    "region": "...",
    "target": "...",
    "category": "Нефтегаз", // Нефтегаз, ВПК, Логистика, Аэродромы и т.д.
    "weapon": "Дрон",
    "details": "...",
    "source": "..."
  },
  "uk": {
    "region": "...",
    "target": "...",
    "category": "...",
    "weapon": "...",
    "details": "...",
    "source": "..."
  },
  "en": {
    "region": "...",
    "target": "...",
    "category": "...",
    "weapon": "...",
    "details": "...",
    "source": "..."
  }
}
```

### 1.4. Требования к тексту описания (`details`):
- **Объем:** строго от 600 до 1000 знаков (букв).
- **Структура:** 4–8 предложений на объект. Чем более значимый объект, тем детальнее описание (значение объекта, мощность, тип производства, влияние на войну).
- **Стиль:** новостной разговорный стиль, без излишней сухости, но без пустословия.
- **Чистота речи:** избегать избыточных эпитетов (*«широчайший спектр»*, *«колоссальный»*), дублирующих оборотов (*«поразившие цель беспилотники всё же добились попадания»* → *«часть всё же достигла цели»*) и лишних уточнений.
- **Фактология:** мощность, дата, перехваченные дроны, жертвы, последствия, возгорания.
- **Языки:** обязательна локализация на `ru`, `uk` и `en`.
- **Координаты:** десятичные градусы (например: `55.7558, 37.6173`).

## Задача 2: Верификация через UserBot (Telegram) и медиа

На удаленном сервере `oracle1` работает Telegram-юзербот:
- **Хост SSH:** `oracle1` (сконфигурирован в `~/.ssh/config`).
- **Путь на сервере:** `/home/ubuntu/UserBot`.
- **Сессия и конфиг:** `config.py`, сессия `userbot_temp`.
- **Обязательные каналы для мониторинга:** `@exilenova_plus` и `@supernova_plus` (а также сопутствующие каналы: `astrapress`, `GeneralStaffZSU`, `DIUkraine`, `Crimeanwind` и др.).

### 2.1. Сбор медиа:
- Для каждого подтвержденного события найти фото и видео за указанную дату: **1–2 видео** и **2–4 фото** (при наличии).
- **Требования к качеству медиа:**
  - Никаких повторных видео или скриншотов с видео (искать оригинальные фото; если фото нет — оставлять только видео).
  - Все фото и видео должны быть разными, без дублей.
  - На медиа должно быть зафиксировано **исключительно само событие** (прилет, взрыв, пожар, последствия).
  - Запрещено размещать видео с посторонним контентом: наложенным текстом, дикторами или кадрами, не относящимися к событию. Если другое видео найти сложно — обрезать неинформативные куски.
  - Длина видео: не короче **3 секунд**.

### 2.2. Обработка медиа (согласно `video-processing`):
- **Сжатие видео (`ffmpeg.exe`):**
  ```powershell
  .\ffmpeg.exe -i "input.mp4" -vf "scale=-2:480" -vcodec libx264 -crf 28 -preset slow -acodec aac -b:a 64k -fs 1.9M "output.mp4" -y
  ```
  *(размер строго < 2 МБ, разрешение 480p)*
- **Сжатие фото (`ffmpeg.exe`):**
  ```powershell
  .\ffmpeg.exe -i "input.jpg" -vf "scale='min(1024,iw)':-1" -q:v 5 "output.jpg" -y
  ```
  *(размер строго < 100 КБ)*
- Готовые медиа сохранить в проект, прописать пути в карточки события в `data.js`.

## Задача 3: Обновление списков закладок (НПЗ и склады)

В файле `app.js` находятся списки мониторинга объектов:
- `refineriesList` (35 крупнейших НПЗ России)
- `warehousesList` (логистические центры и склады Wildberries)
- `ozonWarehousesList` (склады Ozon)

**Действия:**
1. Проверить, были ли атакованы объекты из этих списков за указанную дату.
2. При наличии поражения — обновить статус (`opStatus: 'halted'`, связать с карточкой удара).
3. Проверить статус ранее пораженных объектов: если поступили достоверные данные о завершении ремонта и возобновлении работы — перевести в статус `restored` («Восстановлено / в работе»).

## Финализация и публикация

1. **Расчет дальности:** Запустить в корне проекта:
   ```powershell
   node calc.js
   ```
   Скрипт пересчитает кратчайшее расстояние от линии фронта (опорных городов) до каждого добавленного объекта в `data.js`.
2. **Проверка в браузере:** Убедиться, что новые объекты корректно отображаются на карте, медиа воспроизводятся, нет ошибок в консоли.
3. **Отправка на GitHub:**
   ```powershell
   git add .
   git commit -m "Add deep strikes and media for <ДАТА>"
   git push
   ```
4. **Отчет пользователю:**
   - Отчет должен быть **коротким** и лаконичным: только список добавленных событий, краткие факты по каждому объекту и подтверждение пуша.
   - Сырой JSON/JS код в отчет пользователю **не выводить**.
